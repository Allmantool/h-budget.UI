# Task Specifications

`docs/specs/` contains lightweight, repository-grounded specifications for non-trivial Codex work. A specification is the task contract and persistent handoff record; it maps requested behavior to tests and verification evidence. It is not a replacement for product documentation or a requirement to document trivial changes.

Create a descriptive kebab-case Markdown file from [TEMPLATE.md](TEMPLATE.md) before production implementation. Keep the document concise and update it as decisions, progress, or evidence changes. A future session should be able to determine the goal, scope, confirmed facts, remaining work, and verification status from the specification alone.

Use the [SDD skill](../../.codex/skills/specification-driven-development/SKILL.md) for the workflow and the [verification gate](../../.codex/skills/verification/SKILL.md) before completion.
